# 사용법

## 동작 방식

```
~/Transcribe/inbox/<카테고리>/[모드]/... 에 파일을 넣으면
  → watchdog이 파일을 감지하고, 크기 증가가 멈출 때까지 대기(안정화 확인)
  → PostgreSQL에 작업(job)으로 등록 (대기·처리 중·완료 상태인 같은 내용은 중복 등록되지 않음)
  → 워커가 작업을 하나씩 순차적으로 가져감 (GPU 작업 동시 실행 없음)
  → ffmpeg가 오디오를 16kHz mono WAV로 추출/리샘플링
    (비디오 컨테이너도 처리함. "사전 준비물" 페이지의 "지원하는 입력 포맷" 참고;
    무음 구간을 잘라내지 않으므로 전사 결과의 타임스탬프는 항상 원본과 일치함)
  → 모드에 따라 엔진으로 라우팅:
      asr / asr-multitrack → whisper.cpp (단일 화자, 또는 사전 분리된 트랙)
      diarize               → whispermlx (다중 화자 회의, 화자 라벨 추가)
  → transcript.json(정본) + .md/.txt/.srt 파일을 Obsidian vault에 저장
  → 원본 파일은 아카이브로 이동, macOS 알림 발송
```

## 데몬 재시작 시

데몬이 크래시나 재부팅 등으로 재시작되면, 시작할 때 작업 상태를 다시
맞춥니다. 처리 도중 멈춘 작업은 큐에 다시 등록하고, 원본이 사라졌으면 실패로
처리합니다. 전사는 끝났지만 아카이브로 옮기지 못한 작업은 이때 아카이브합니다.

## 파일 넣기

데몬이 실행 중일 때 [인박스 폴더 구조](/ko/guide/inbox-layout)에 맞춰 파일을
복사하거나 옮겨 넣으면 됩니다. 따로 실행할 명령은 없습니다. 작업으로 등록되는
시점은 모드에 따라 다릅니다.

- `asr` / `diarize`: 파일 크기가 5초 동안 늘지 않으면 복사가 끝난 것으로 보고
  작업으로 등록합니다.
- `asr-multitrack`: 세션 폴더 안에 60초 동안 변화가 없어야 등록합니다. 트랙을
  하나씩 넣는 도중에 불완전한 세션이 등록되지 않도록 기다리는 시간입니다.
  트랙을 모두 넣은 뒤 1분 정도 기다리세요.

작업은 한 번에 하나씩 순서대로 처리하며, GPU 작업을 동시에 실행하지 않습니다.
같은 내용의 작업이 `PENDING`, `PROCESSING`, `COMPLETED` 상태이면 파일을 다시
넣어도 중복 등록되지 않습니다. 파일 이름이 아니라 내용 해시로 판별하므로 이름만
바꿔 넣어도 마찬가지입니다. 이전 작업이 `FAILED`라면 같은 파일을 인박스에 다시
넣을 때 새로 등록됩니다.

## 실패했을 때

- 작업 상태가 `FAILED`로 바뀌고 에러 메시지가 DB에 기록됩니다.
- 원본 파일은 인박스에 그대로 남습니다. 아카이브로 옮기거나 삭제하지 않습니다.
  전사 결과는 보통 저장되지 않습니다. 저장은 끝났지만 완료 기록만 실패한 드문
  경우에는 출력 폴더에 이미 있을 수 있습니다.
- macOS 알림이 뜹니다. 제목은 `전사 실패`, 본문은
  `<카테고리> · <원본 이름>: <에러 메시지>`입니다.
- 실패한 작업은 데몬을 재시작해도 **자동으로 재시도하지 않습니다**. 파일이
  인박스에 남아 있어도 시작 시 스캔은 "이미 실패한 작업"으로 보고 건너뜁니다.
  고장 난 파일 하나 때문에 재시작할 때마다 GPU를 수십 분씩 쓰지 않기
  위해서입니다. 재시도는 아래 방법으로 직접 해야 합니다.

## 상태 확인

작업 상태와 이력은 로그 파일이 아니라 PostgreSQL에 저장됩니다. 상태 값은
`PENDING`(대기), `PROCESSING`(처리 중), `COMPLETED`(완료), `FAILED`(실패)
네 가지입니다.

```sh
psql "$DATABASE_URL" -c "SELECT id, status, category, processing_mode, source_path, error_message, created_at FROM transcription_job ORDER BY created_at DESC LIMIT 10;"
```

실패한 작업만 보려면 다음을 실행합니다.

```sh
psql "$DATABASE_URL" -c "SELECT id, source_path, error_code, error_message FROM transcription_job WHERE status = 'FAILED';"
```

`psql`과 아래의 `retry` 명령을 쓰려면 셸에 `DATABASE_URL`이 있어야 합니다.
plist에 넣은 값은 데몬 프로세스에만 적용되므로, 터미널에서는
`export DATABASE_URL=...`를 따로 실행하세요.

## 재시도

위 쿼리로 확인한 작업 id를 넣어 프로젝트 디렉터리에서 실행합니다.

```sh
uv run transcribe-inbox retry <job-id>
```

이 명령은 작업 상태를 `FAILED`에서 `PENDING`으로 되돌리기만 합니다. 실제
처리는 데몬이 다음 폴링(약 5초 간격)에서 가져갑니다. 아래 두 조건을 모두
만족해야 하며, 하나라도 맞지 않으면 상태를 바꾸지 않고 에러 메시지를 출력한 뒤
종료합니다.

1. 작업 상태가 `FAILED`여야 합니다. `PENDING`, `PROCESSING`, `COMPLETED`
   상태는 거부합니다.
2. DB에 기록된 원본 경로에 파일(또는 세션 폴더)이 남아 있어야 합니다. 실패한
   원본을 인박스 밖으로 옮겼거나 지웠다면 재시도할 수 없습니다.

파일을 인박스에서 잠시 뺐다가 다시 넣어도 같은 효과가 납니다. 내용이 같아도
실패했던 작업은 다시 큐에 올라갑니다. 다만 파일 자체가 원인이라면(손상,
지원하지 않는 코덱 등) 몇 번을 재시도해도 결과는 같습니다.
