# 결과물과 아카이브

## 성공했을 때

1. 전사 결과 파일 4개를
   `~/Obsidian/second-brain/Transcripts/<카테고리>/<라벨>/`에 저장합니다.
   ```
   transcript.json   # 정본 — 세그먼트/단어 타임스탬프, 화자 라벨, 엔진·모델 메타데이터
   transcript.md     # [00:01:23] 화자: 텍스트 형태
   transcript.txt    # 타임스탬프 없이 본문만
   transcript.srt    # 자막 포맷
   ```
   `<라벨>`은 `asr`, `diarize` 모드에서는 원본 파일 이름에서 확장자를 뺀 값이고,
   `asr-multitrack` 모드에서는 세션 폴더 이름입니다. 결과는 임시 폴더에 모두
   쓴 뒤 폴더째 이름을 바꾸는(rename) 방식으로 저장합니다. 그래서 절반만 쓰인
   폴더가 vault에 보이지 않습니다.
2. 원본은 `~/Transcribe/archive/<카테고리>/<모드>/`로 이동하며, 인박스에서는
   사라집니다. 모드 폴더 없이 넣은 파일도 아카이브에서는 `asr/` 아래에
   들어갑니다. 같은 이름이 이미 있으면 덮어쓰지 않고 내용 해시 앞 8자리를 붙여
   저장합니다. 예를 들어 `2주차.m4a`는 `2주차-1a2b3c4d.m4a`가 되고, 이 이름도
   있으면 `2주차-1a2b3c4d-1.m4a`, `-2` 순으로 붙습니다. 세션 폴더도 같은
   방식으로 `2026-09-08-1a2b3c4d`가 됩니다. 따라서 아카이브에 이미 있는 원본이
   모르는 사이에 사라지지 않습니다.
3. macOS 알림이 뜹니다. 제목은 `전사 완료`, 본문은 `<카테고리> · <원본 이름>`입니다.
4. DB의 작업 상태가 `COMPLETED`로 바뀝니다.

실제로는 전사 결과 폴더를 저장한 직후에 `COMPLETED`를 기록하고, 그 뒤에 알림과 아카이브를 처리합니다. 둘 중 하나가 실패해도 작업은 `COMPLETED`로 남고 전사 결과는 이미 저장된 상태입니다. 이때 원본은 인박스에 남아 있다가 다음 데몬 시작 때 아카이브됩니다.
