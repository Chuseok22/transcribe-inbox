# 输出与归档

## 成功时

1. 4 个转写结果文件会被发布到 `~/Obsidian/second-brain/Transcripts/<类别>/<标签>/`：
   ```
   transcript.json   # 정본 — 세그먼트/단어 타임스탬프, 화자 라벨, 엔진·모델 메타데이터
   transcript.md     # [00:01:23] 화자: 텍스트 형태
   transcript.txt    # 타임스탬프 없이 본문만
   transcript.srt    # 자막 포맷
   ```
   （各行注释依次为：正本 — 片段/单词时间戳、说话人标签、引擎·模型元数据；`[00:01:23] 화자: 텍스트` 形式，即 `[时间戳] 说话人: 文本`；没有时间戳，只有正文；字幕格式。`<카테고리>` = 类别，`<라벨>` = 标签。）
   `<标签>` 在 `asr`/`diarize` 下是原始文件名去掉扩展名后的值，在 `asr-multitrack` 下则直接是会话文件夹的名称。发布采用的是先全部写入临时文件夹、再整体 rename 的方式，因此 vault 中不会出现只写了一半的文件夹。
2. 原始文件会被**移动**到 `~/Transcribe/archive/<类别>/<模式>/`（它会从收件箱中消失）。省略模式文件夹放入的文件，在归档中也会进入 `asr/` 下。如果已存在同名文件，绝不会覆盖，而是附加内容哈希的前 8 位后保存 — `2주차.m4a` → `2주차-1a2b3c4d.m4a`（如果连这个也已存在，则依次为 `2주차-1a2b3c4d-1.m4a`、`-2` …）。会话文件夹也以同样的方式变成 `2026-09-08-1a2b3c4d`。也就是说，已进入归档的原始文件不会被悄无声息地丢失。
3. 会弹出 macOS 通知 — 标题 `전사 완료`（“转写完成”），正文 `<카테고리> · <원본 이름>`（`<类别> · <原始文件名>`）。
4. 数据库中的任务状态变为 `COMPLETED`。
