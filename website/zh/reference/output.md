# 输出与归档

## 成功时

1. 把 4 个转写结果文件保存到 `~/Obsidian/second-brain/Transcripts/<类别>/<标签>/`。
   ```
   transcript.json   # 정본 — 세그먼트/단어 타임스탬프, 화자 라벨, 엔진·모델 메타데이터
   transcript.md     # [00:01:23] 화자: 텍스트 형태
   transcript.txt    # 타임스탬프 없이 본문만
   transcript.srt    # 자막 포맷
   ```
   各行注释依次为：正本，含片段和单词时间戳、说话人标签、引擎和模型元数据；`[00:01:23] 说话人: 文本` 形式；只有正文，不含时间戳；字幕格式。

   `<标签>` 在 `asr`、`diarize` 模式下是原文件名去掉扩展名后的部分，在 `asr-multitrack` 模式下是会话文件夹名称。结果先全部写入临时文件夹，再整体重命名（rename），所以 vault 中不会出现只写了一半的文件夹。
2. 原文件移到 `~/Transcribe/archive/<类别>/<模式>/`，从收件箱中消失。没有放在模式文件夹中的文件，在归档中也放在 `asr/` 下。如果已有同名文件，不会覆盖，而是加上内容哈希的前 8 位再保存。例如 `2주차.m4a` 会变成 `2주차-1a2b3c4d.m4a`，如果这个名称也已存在，则依次加 `2주차-1a2b3c4d-1.m4a`、`-2`。会话文件夹也按同样的方式变成 `2026-09-08-1a2b3c4d`。因此，归档中已有的原文件不会在不知情的情况下丢失。
3. 弹出 macOS 通知。标题为 `전사 완료`（转写完成），正文为 `<카테고리> · <원본 이름>`（类别 · 原文件名）。
4. 数据库中的任务状态变为 `COMPLETED`。

实际上，转写结果文件夹保存完成后就会记录 `COMPLETED`，之后才处理通知和归档。这两步中任何一步失败，任务都仍是 `COMPLETED`，转写结果也已经保存。此时原文件会留在收件箱中，在下次守护进程启动时归档。
