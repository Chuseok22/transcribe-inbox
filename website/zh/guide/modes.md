# 支持的模式

模式恰好只有 3 种。

| 模式 | 何时使用 | 引擎 | 说话人标签 |
|---|---|---|---|
| `asr`（默认值） | 只有一个说话人的录音 — 讲课、自己说话的备忘 | whisper.cpp | 无 |
| `asr-multitrack` | 已经**按说话人分好文件**的录音 — 参会者各自用自己的设备录音的会议 | whisper.cpp（每个音轨各运行一次） | 音轨文件名（不含扩展名） |
| `diarize` | 多个说话人**混在同一个文件里**的录音 — 用一支麦克风录制的会议 | whispermlx | 由说话人分离模型添加的匿名标签 |

`asr` 与 `diarize` 的区别不在转写质量，而在于是否区分说话人。如果不需要区分说话人，就没有理由使用 `diarize` — 因为会额外运行对齐（alignment）和说话人分离步骤，耗时要长得多。

如果已经有按说话人分好的文件，`asr-multitrack` 比 `diarize` 更好。说话人分离属于推断，可能出错；而 `asr-multitrack` 已经确定了哪个文件属于谁，说话人标签没有出错的余地。

## `asr` — 单个说话人（默认值）

省略模式文件夹即可：

```
~/Transcribe/inbox/
└── 강의/
    └── 2주차.m4a
```

- 转写结果：`~/Obsidian/second-brain/Transcripts/강의/2주차/`
- 归档：`~/Transcribe/archive/강의/asr/2주차.m4a`

即使像 `~/Transcribe/inbox/강의/asr/2주차.m4a` 这样显式指定模式，结果也完全相同。

## `diarize` — 多个说话人混在一个文件里的会议

```
~/Transcribe/inbox/
└── 회의/
    └── diarize/
        └── 2026-09-08.m4a
```

- 转写结果：`~/Obsidian/second-brain/Transcripts/회의/2026-09-08/`
- 归档：`~/Transcribe/archive/회의/diarize/2026-09-08.m4a`
- 说话人标签是说话人分离模型自动添加的匿名标签 — 并不是真实的人名，谁是谁需要你查看转写稿后自行对应。
- 只有这个模式需要 `HUGGINGFACE_TOKEN` 以及同意模型条款（参见[前置条件](/zh/getting-started/prerequisites)）。

## `asr-multitrack` — 按说话人分成多个文件的会议

在模式文件夹下创建一个会话文件夹，并把各说话人的文件放进去：

```
~/Transcribe/inbox/
└── 회의/
    └── asr-multitrack/
        └── 2026-09-08/
            ├── 김철수.m4a
            └── 홍길동.m4a
```

- 整个会话文件夹 `2026-09-08` 就是一个任务。各音轨分别转写后，按时间顺序排序并合并为**一份转写稿**。
- **说话人标签是文件名去掉扩展名后的值** — 在上面的示例中是 `김철수`、`홍길동`。因此请直接把文件名起成说话人的名字。
- 转写结果：`~/Obsidian/second-brain/Transcripts/회의/2026-09-08/`
  （直接使用的是**会话文件夹的名称**，而不是文件名）
- 归档：`~/Transcribe/archive/회의/asr-multitrack/2026-09-08/`
  （不是逐个文件，而是整个会话文件夹一起移动）

**注意 — 会话文件夹中只能放各说话人的音频文件。**

- 会话文件夹内（非隐藏文件的）**所有文件都会被登记为音轨。** 如果混入了 `.txt`、`.dat` 之类的元数据文件，这些文件也会被尝试作为音频解码并失败，**整个会话都会变成 `FAILED`**。失败的任务不会自动重试（参见[使用方法](/zh/guide/usage)中的“失败时”）。
- **假定所有音轨都在同一时刻开始。** 不支持按音轨校正起始时间点（偏移量），一律设为 0 秒后按时间顺序合并。如果各音轨的录音起始时间点不一致，合并后的转写稿中发言顺序可能会错乱，因此请先确认各说话人的文件是否是从同一时间点开始录制的。
- 只在会话文件夹的**正下方**放置文件。不能在其中再创建子文件夹（参见[收件箱目录结构](/zh/guide/inbox-layout)中的“含义不明确的路径”）。

### 示例：用 Craig 录制 Discord 会议的情况

在 Craig 中以多音轨方式下载的文件夹里，除了各说话人的音频外，还一并包含元数据文件：

```
craig-xxxxxxxx/
├── 1-alice.aac             # 화자별 트랙 (앞에 번호가 붙음)
├── 2-bob.aac
├── 3-carol.aac
├── info.txt               # 메타데이터 — 넣으면 안 됨
└── raw.dat                # 원본 데이터 — 넣으면 안 됨
```

不要把这个文件夹整个放进去，而是**只挑出音频文件，复制到会话文件夹**中。由于说话人标签来自文件名，建议去掉编号前缀（`1-alice.aac` → `alice.aac`）：

```
~/Transcribe/inbox/
└── 회의/
    └── asr-multitrack/
        └── 2026-09-26/          ← 세션 폴더
            ├── alice.aac
            ├── bob.aac
            └── carol.aac
```

上面两个目录树中的注释：`# 화자별 트랙 (앞에 번호가 붙음)` = 各说话人的音轨（前面带有编号）；`info.txt`/`raw.dat` 的注释 = 元数据/原始数据 — 不能放入；`← 세션 폴더` = 会话文件夹。

转写成功后，收件箱中的原始文件会被**移动**到归档，因此请把原始下载文件夹**复制**进去，而不要移动它。
